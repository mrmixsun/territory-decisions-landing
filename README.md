# Прототип сайта Концепции

Рабочая папка веб-прототипа Концепции. Итог — цельный адаптивный лендинг и страница полного текста, которые можно открыть локально в браузере. Визуально это близкая к реальному сайту версия, а не служебный макет с крупными плашками «внутренний прототип».

Исходное подробное ТЗ хранится в проектной базе знаний отдельно от этого репозитория.

## Папки и зоны ответственности

- `content/` — тексты, подписи схем, фактологическая сверка; зона агента текста.
- `design/` — токены, редактируемая графика, спецификация компонентов и пакет для последующей сборки в Figma; зона агента дизайна.
- `site/` — исходники работающего сайта и инструкция запуска; зона агента вёрстки.

Агенты могут читать весь проект, но одновременно не редактируют чужую зону. Интеграционные правки после их сдачи делает оркестратор.

Версии текста лендинга сохранены в [content/versions/](content/versions/README.md). Активную редакцию сайт берёт из `content/landing.json`.

Строгие редакции `s1.0` и `s1.1-desktop` вынесены на отдельные страницы [Figma для комментариев](https://www.figma.com/design/lOlDkmqAITDsVrbvJh5NRK). Порядок работы и ограничения переноса описаны в [design/figma-review.md](design/figma-review.md). Опубликованный сайт пока остаётся на версии `v2-человечная`; новые редакции готовятся отдельно и не отправляются в публичный репозиторий без согласования.

## Просмотр и публикационная копия

Инструкция запуска и проверки — в [site/README.md](site/README.md). Папка `docs/` содержит проверенную статическую сборку для GitHub Pages. После правок текста, дизайна или кода нужно снова собрать сайт и обновить `docs/` содержимым `site/dist/`.

## Уточнения к ТЗ для этого запуска

1. Не тратить время на две разные редакции «для внутреннего» и «для публичного». Делать один близкий к реальности сайт с корректным содержанием. Служебный статус прототипа фиксировать в файлах проекта, а не выводить большим баннером на первом экране.
2. Не выдумывать утверждение Концепции государственным органом, реквизиты актов, количественные эффекты, контакт или авторство. Если данные не согласованы, не заполнять их фальшивыми значениями. Спорные места вынести в отдельный список.
3. Тестовая версия опубликована по прямому поручению Михаила в [отдельном репозитории](https://github.com/mrmixsun/territory-decisions-landing). Это не утверждение текста Концепции для официальной коммуникации.
4. Этот вложенный Git-репозиторий содержит только прототип. Репозиторий **всей базы знаний GEMS** не использовать как публичный хостинг и не отправлять в него материалы сайта автоматически.
